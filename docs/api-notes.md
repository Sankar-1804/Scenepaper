# API Notes

Every external API call the app makes must be documented here: endpoint, purpose, auth. Updated as integrations are actually built — this file currently reflects **decisions made**, not yet **code written**.

## Images: Pexels (decided, session 2)

- **Choice:** Pexels, over Unsplash.
- **Why:** Simple key-based auth, generous free rate limit, good per-keyword search — fits the per-scene image matching need in Tier 1. Unsplash was the other option considered; no strong technical reason to prefer it here, so not pursued.
- **Auth:** API key (Pexels developer key). Not yet obtained/configured.
- **Status:** Decided, not yet integrated. Endpoint/usage details to be added here once the image-fetch code (api-integration-agent scope) is actually written.

## Runtime LLM API: Google Gemini API (DECIDED)

The ideation call (topic → 3–4 verified candidate one-liners) and the structuring call (verified source → full ScenePaper JSON schema) both need a runtime LLM API — separate from Claude Code Enterprise access, which is a dev tool only. Tracked in issue #4, now resolved.

- **Decision:** Google AI Studio / Gemini API. Project created and API key generated by the user.
- **Model:** `gemini-2.5-flash` (primary candidate — reassess against `gemini-2.5-flash-lite` if free-tier RPM/RPD becomes a constraint during dev or the demo).
- **Why:** Native `response_schema` support genuinely constrains output to a JSON schema at the decode level — the strongest structured-output guarantee found across everything researched (PlatformAI, OpenRouter, Groq, Cerebras, Together/Fireworks/DeepInfra, Mistral). This directly matters for reliably filling the nested `hooks[]`/`scenes[]`/`delivery_notes[]` schema. Reasoning quality is also a clear step up from the free open-weight models on OpenRouter.
- **Cost:** confirmed genuinely $0 on the Free tier — no credit card attached, no billing account linked. **Do not link a Cloud Billing account** — the moment one is linked the project can move to a paid tier; staying unlinked is the only way to guarantee zero cost. See [ai.google.dev/gemini-api/docs/billing](https://ai.google.dev/gemini-api/docs/billing) and [ai.google.dev/gemini-api/docs/rate-limits](https://ai.google.dev/gemini-api/docs/rate-limits).
- **Free tier rate limits (approximate, verify exact current numbers at aistudio.google.com/rate-limit for this project — Google changed quotas as recently as Dec 2025):** `gemini-2.5-flash` ~10 RPM / 250 RPD; `gemini-2.5-flash-lite` ~15 RPM / 1,000 RPD (most generous); `gemini-2.5-pro` ~5 RPM / 100 RPD (tightest). Shared ~250K TPM across models.
- **Auth:** API key. **Stored in a local `.env` file (gitignored), not committed, not pasted into any chat/log.** Env var name: `GEMINI_API_KEY` (to be finalized when the actual client code is written).
- **Status:** Decided. Key generated by the user, not yet wired into any code.
- **Rate-limit note (session-2 addendum):** the prompt-injection defense requires **two separate Gemini calls per paper** (Call A verification, Call B structuring), plus the query-generation call for ideation — roughly 3 calls per paper generated, not 1. Worth re-checking free-tier RPM/RPD headroom against this once real volume is known, rather than assuming the original single-call budget still holds.

## Search: SearXNG (DECIDED, session-2 addendum — supersedes the earlier Wikipedia/news-API plan)

- **Decision:** self-hosted SearXNG (metasearch), not Wikipedia's API or a structured news API as originally planned in the main handoff. Made in a separate planning conversation, confirmed as final when raised here.
- **Why the reversal:** not fully documented in this repo — the addendum states it as a settled decision without restating the original Wikipedia-based reasoning being overturned. Worth asking directly if this needs a fuller rationale for the Day 4 retro talk.
- **Auth:** none — SearXNG has no API key model, but it also **has no built-in authentication of its own**, so wherever it's hosted can't sit on the open internet unprotected (same caveat as Voicebox).
- **Hosting: still open**, tracked in issue #21 — Docker isn't installed in this dev environment, so the default self-host path needs an alternative resolved before Phase 2 is buildable.
- **Usage pattern:** noisy results (news/blogs/Reddit/SEO farms mixed together) — domain-quality scoring must run before clustering, and snippets alone are too thin to write an honest one-liner from, so expect to fetch the top 1-2 full results per cluster. This adds real latency, which interacts with the Catalyst function-timeout spike (issue #2).
- **Status:** Decided (search technology), not hosted, not integrated, not tested.

### Shelved / not pursued further

- **PlatformAI v2 API** (Zoho internal) — ruled out for hackathon use. Requires the calling product to already be a registered Zoho "service" in IAM, a `portal_id` provisioned via an endpoint that only accepts a live User IAM Ticket, and — for the ZKS shared-key path — email onboarding with the platformai@zohocorp.com team plus (for IDC) DPIA/Legal approval. Not achievable inside the hackathon window. Full findings on file if this needs revisiting post-hackathon (real product roadmap, not this build).
- **OpenRouter free tier** — solid runner-up, kept here for reference in case Gemini's free-tier quota becomes a real constraint mid-demo: `meta-llama/llama-3.3-70b-instruct:free` (20 req/min, 50-1,000 req/day depending on account credit history). Structured-output support is inconsistent per-model, weaker guarantee than Gemini's native `response_schema`.
- **Groq, Cerebras, Mistral La Plateforme** — all genuinely free/self-serve, researched as alternatives. Cerebras had the most generous quota but only an 8K-token context cap on free tier and its "free trial" framing needs a double-check before relying on it. Not chosen since Gemini already covers both cost and structured-output reliability better.
- **Together.ai, Fireworks.ai, DeepInfra** — ruled out, no ongoing free tier, only one-time trial credits.
